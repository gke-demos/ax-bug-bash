# Polyglot Five-Service HTTP Mesh and Zero-Downtime Pre-Warmed Git Hot-Reload

In `LIVE_GKE` mode, we run the 5 Retail Storefront microservices (`storefront-web:3001` in Node.js 22 native TypeScript, `checkout-service:8081` in Go, `shipping-service:8082` in Go, `pricing-service:8083` in Python/FastAPI, and `inventory-service:8084` in Rust/Axum) plus `storefront-git:8090` (reverse-proxied at `storefront:3001/git/*`) as independent Kubernetes `Deployment`s and `Service`s built from a single shared pre-warmed `storefront-polyglot` image (`GOCACHE`, `CARGO_HOME` + `/opt/cargo-target`, `/opt/ax-venv`, `node_modules`) with zero synthetic incident flags, while keeping `internal/storefront.Runtime` in-process for `SIMULATED` mode (`go test` and offline runs). Each pod runs a PID-1 Go `Hot-Reload Supervisor` that owns persistent Prometheus `/metrics` counters, clones `storefront.git` (`baseline-v1` baseline tag for `< 3s` resets), receives selective `git diff` reload webhooks only for modified services, incrementally compiles and boots a new loopback child process, and atomically flips traffic only after `/healthz` passes so broken builds preserve the last healthy revision with zero dropped requests. On `POST /api/cart/checkout`, `storefront-web` propagates `X-Storefront-Request-ID` across validation calls to all 4 domain services before failing any checkout so every implicated service in a multi-service incident emits real `HTTP 500` metrics and language-native stack traces in a single transaction.
