# Dual-Mode Execution and Zero-Trust In-Sandbox Bug Bash Coordination

We enforce an explicit `Execution Mode` (`LIVE_GKE` when `AX_SERVER_ADDR` is configured vs. `SIMULATED` for hermetic `go test` and offline runs) where `LIVE_GKE` fails closed rather than ever falling back to in-process triage or TDD inside `ax-observer`. In `LIVE_GKE`, a reproducible `deploy/ax-server/` control-plane overlay attaches least-privilege cluster-internal `EgressPolicy` rules before `ResumeActor` so sandboxed tasks remain completely unprivileged: `ax-observer` dispatches non-blocking Root Tasks (`202` / `"status": "dispatched"` within Alertmanager's 10s webhook window), the Root Task spawns isolated Child Tasks over `ax.v1alpha1.AX` gRPC, each Child Task runs its real headless Coding Harness CLI (`antigravity`, `opencode`, or `pi`) with a 2-attempt Red-Green verification loop and pushes `refs/heads/fix/<task-name>` before `OnCommandExit` → `SuspendTask`, and the Root Task gates its `main` merge on verified child branches within a `120s` deadline. `AX Observer` polls read-only `substrate.ateapi.v1.Control` (`role: viewer`), `ax-server` `ListTasks`, and `GET <MODEL_GATEWAY_URL>/api/gateway/sessions` to surface live worker-slot reclamation alongside honest `Execution Mode` and `Source Provenance` (`LIVE` vs. `FIXTURE`) indicators.
