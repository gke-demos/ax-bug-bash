# Two-Tier Evaluation Suite, Sequential `baseline-v1` Chaos Soak, and GCP Dual-Export Verification

We split automated verification into a fast, offline `SIMULATED` matrix (`make eval`, running 20 trajectories at `MaxConcurrency = 4` in `< 60s` alongside static Phase 2 manifest and `Architecture Topology Catalog` drift checks) and an opt-in `LIVE_GKE` sequential chaos soak (`make eval-live-gke`, running at `MaxConcurrency = 1` so parallel runs never collide on the shared `storefront.git` `main` branch or oversubscribe the 4-pod `ateworker-gvisor` `WorkerPool`). Each `LIVE_GKE` soak step sets the active `default_harness` (`antigravity`, `opencode`, `pi`, `multi`), drives a real `POST /api/cart/checkout` through in-cluster Prometheus (`[15s]`) + Alertmanager + Loki (`<= 15s`), enforces strict `ExecutionMode == "LIVE_GKE"`, `SourceProvenance == "LIVE"`, `0`-active-slot `SuspendTask` reclamation, and `< 10s` selective hot-reload (`HTTP 500` → `200`), and then runs `POST /api/incidents/reset` (`baseline-v1`) plus a `<= 20s` Prometheus `/api/v1/alerts` drain so `StorefrontHTTP500Spike` (`group_by: ['alertname']`, `repeat_interval: 30m`) re-fires cleanly on the next incident. At the end of the soak, the verifier polls Google Cloud Logging and Google Cloud Managed Service for Prometheus (`<= 60s`, attaching `X-Goog-User-Project` when using developer ADC tokens) and writes a stage-safe scrubbed report to `/tmp/ax-live-gke-eval-report.json`.
