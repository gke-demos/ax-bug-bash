# In-Cluster Prometheus, Alertmanager, Loki, and Grafana with GCP Dual-Export

We deploy upstream Prometheus, Alertmanager, Loki, and Grafana (`:3002` in `LIVE_GKE`) in-cluster with a 5-second scrape/evaluation interval across all 5 microservice `/metrics` endpoints, an `increase(storefront_http_requests_total{status="500"}[15s]) > 0` (`for: 0s`) PromQL rule guaranteeing 3 scrape samples in range, and Alertmanager `group_by: ['alertname']` (`group_wait: 1s`) consolidation so multi-service HTTP 500 checkouts fire a single unified webhook (`POST /api/webhooks/alertmanager`) within 3 to 5 seconds. Each service dual-emits structured JSON error logs (`X-Storefront-Request-ID`) to container `stdout` for Google Cloud Logging and asynchronously to Loki `/loki/api/v1/push` (queried via `/loki/api/v1/query_range` by `AlertmanagerBridge`), while `PodMonitoring` scrapes `monitoring-target: retail-storefront` at `interval: 10s` to export metrics to Google Cloud Managed Service for Prometheus without hitting Cloud Monitoring's 5-second minimum sampling floor on scrape jitter.
